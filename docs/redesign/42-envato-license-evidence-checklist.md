## Onde ficam os certificados — convenção definida nesta fase

**`vedium-references/licenses/envato/`** — fora de `public/` (os certificados nunca precisam ser servidos pelo site, então não fazem sentido dentro de uma pasta de assets públicos).

### Verificação real da política de Git (feita nesta fase, não assumida)

`vedium-references/` (a pasta inteira, incluindo esta nova subpasta) **já está fora do controle de versão** — mas via `.git/info/exclude`, não via `.gitignore`. Essa é uma diferença importante: `.git/info/exclude` é **local a este clone**, nunca é commitado nem compartilhado — alguém clonando o repositório do zero, ou usando outra máquina, **não teria essa proteção** e poderia commitar um certificado com dado de conta/pessoal por engano.

**Correção aplicada nesta fase**: adicionada uma linha em `.gitignore` (arquivo versionado, viaja com o repositório) cobrindo `vedium-references/` — reforço de segurança puro, sem efeito em nenhum comportamento de runtime/produção. A partir de agora, a proteção existe em qualquer clone do repositório, não só nesta máquina.

Se algum certificado contiver dado de conta/pessoal (nome do titular da assinatura, e-mail, etc.), ele **NÃO deve ser commitado automaticamente** — a exclusão via `.gitignore` já impede isso por padrão, mas vale reforçar manualmente com `git status` antes de qualquer commit que toque essa pasta.
